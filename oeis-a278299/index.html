Four new terms of an integer sequence

How small can a patch of grid squares be if every pair of n colors has to touch somewhere? I helped push the answer from n = 18 to n = 22 in the On-Line Encyclopedia of Integer Sequences.

Overview

OEIS A278299 asks for the fewest grid squares you need to color with n colors so that every color sits edge-to-edge with every other color at least once. The answers are hard to pin down: until 2026, only a(2) through a(11) were known exactly. This page is about the part I worked on.

01 The problem

Make every color touch every other color

Take n colors, numbered 1 to n. Color some connected squares of graph paper (a polyomino) so that, for every pair of different colors, at least one square of the first shares an edge with a square of the second. Corners don’t count. a(n) is the smallest number of squares that can do it.

For four colors there are six pairs to cover, and six squares are enough: in the shape on the right, the top 1 touches 4 and 3, that 4 touches 2, the left 4 touches 3, 3 touches 2, and 2 touches the bottom 1. Five squares can’t do it, so a(4) = 6.

Kagey’s Square Game turns this into a puzzle: you click numbers onto a grid, it marks pairs that repeat in red, and a valid grid you submit becomes an upper bound for the sequence. Kagey traces the idea to a ≠ b ≠ c ≠ a written on the board in a linear algebra class; the one-dimensional version is a solved problem, and Alec Jones suggested the two-dimensional one.

02 Why it’s hard

A huge search with a bound to beat

Two things have to be chosen at once: the shape, and the color of every square. For n = 22 and a fixed 132-square shape there are 22132, about 10177, ways to color it, and the number of possible shapes grows exponentially too. Nobody checks those one by one.

What makes progress possible is a lower bound. Peter Exley gave the one in the entry:

a(n) ≥ max( ⌊(n2 + n + 5)/4⌋, n·⌈(n − 1)/4⌉ )

Edge bound

Each of the n(n−1)/2 pairs needs its own shared edge. A polyomino with k squares and perimeter P has (4k − P)/2 internal edges, and compact shapes have the smallest perimeter, so k can’t be too small. The difference between internal edges and pairs is the slack: how many edges can be wasted on repeats.

Contact bound

Each color has to touch n − 1 others, and a square has at most four neighbors, so every color needs at least ⌈(n − 1)/4⌉ squares. For n = 22 that is 6 squares per color, 132 in all.

A lower bound settles the “nothing smaller works” half of a proof. If you can then show one coloring that hits the bound exactly, the value is proved. The hard part is finding that coloring when the slack is close to zero, or proving none exists.

03 Approach 1

Parallel simulated annealing

My first tool was a heuristic search, written in C++17 with OpenMP. It works on a score: the number of color pairs that don’t touch yet. Zero means a valid coloring.

  1. Start random. Grow a random connected shape of k squares and fill it with every color at least once plus random extras.
  2. Make a small change. Move one square to another spot on the edge of the shape, swap the colors of two squares, or recolor one square.
  3. Accept or undo. Keep any change that doesn’t make the score worse. Keep a worse one with probability e−Δ/T, where the temperature T cools geometrically from 5 to 0.01, so the search can climb out of dead ends early and settles down later.
  4. Run many at once. Each thread runs its own independent attempts under dynamic scheduling. The first thread to reach zero sets an atomic flag and the rest stop; if none succeeds, k goes up by one.

A second version replaced the hash map with a flat grid array, updated the score incrementally instead of recounting every edge, kept shapes connected when squares move, and added parallel tempering, where threads at different temperatures swap configurations. I then wrote a CUDA annealer that gives each candidate shape its own GPU thread block, with the threads counting edges cooperatively.

The runs went to the BYU supercomputer as SLURM batch jobs. The job script rebuilds the binary whenever it lands on a node with a different CPU instruction set, since it is compiled with -march=native.

What annealing could and couldn’t do

It finds good colorings fast. In logged runs it found a 100-square coloring for n = 19 in about 23 minutes on 32 threads, and an 80-square one for n = 17 in about half an hour. But the true values are 96 and 77. Near the bound, where the slack is tiny, random moves rarely hit one of the few valid colorings, and a heuristic can never prove that a size is impossible.

04 Approach 2

Exact search with a SAT solver

A SAT solver takes a long list of true/false constraints and either finds values that satisfy all of them or proves that none exist. To use one here, I fix a candidate shape and translate the question into Boolean variables that say which color each square gets, with clauses saying that each square gets exactly one color and that every pair of colors meets across at least one shared edge. Candidate shapes are enumerated by perimeter, which the edge bound limits.

The search for n = 21 at 116 squares came back satisfiable: the solver returned a complete coloring. Since 116 is the lower bound for n = 21, that one example proves a(21) = 116. The same work settled a(22) = 132, which is exactly the contact bound, with the coloring in Fig. 2. Each returned coloring is checked by a separate verifier that shares no code with the encoder. Ryan Lee’s SAT search for a(20) = 106 worked the same way: the example it returned meets the bound.

I built the SAT tooling in Python with the CaDiCaL solver, with help from Claude Code.

06 Takeaways

What I learned, and the limits

  • Pick the tool by the slack. When a size leaves plenty of room for repeated pairs, annealing finds colorings quickly. When the slack is near zero (the a(19) coloring has exactly one spare edge), an exact search is the better bet.
  • A bound turns an example into a proof. All four new values sit exactly on Exley’s lower bound, so each one is proved by a single verified coloring. That is also the limit of what I have shown: none of these proofs needed the solver to rule a size out.
  • The open cases are harder. For a(23), a(24), a(25) and a(27) the gap between bounds is 2 to 5 squares. Closing it means either a coloring on the bound or proving that every shape of that size fails, which is far more expensive.
  • Check results independently. A verifier that shares no code with the search is cheap insurance before submitting anything to the OEIS.
